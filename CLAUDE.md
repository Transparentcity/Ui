# Transparent City — UI repo

## Waste module

The admin-only waste module lives at `/waste` (landing page = findings by
category; tabs: By category / By department / Reports). Architecture, data
flow, the never-blank run merge, and the weekly-refresh (job #2) wiring are
documented in `src/components/waste/README.md` — read that before changing
anything under `src/components/waste/` or `src/app/waste/`. The city picker
is backend-driven (`configured && launched` from `/api/admin/waste/cities`);
launching a new waste city requires no UI change.

## Weekly QA

The automated weekly QA runs via `.github/workflows/weekly-qa.yml` every Thursday at 7 AM PT.
It executes `scripts/weekly-qa/index.mjs`, which uses Playwright (full JS rendering) and the
live sitemap API to resolve city slugs automatically.

### Canonical city dashboard URLs

When visiting dashboards manually (e.g. with WebFetch), always use these exact slugs.
The abbreviated forms (`/c/sf`, `/c/nyc`) do not exist.

| City        | URL                                          |
|-------------|----------------------------------------------|
| SF          | https://transparent.city/c/san-francisco     |
| Oakland     | https://transparent.city/c/oakland           |
| Chicago     | https://transparent.city/c/chicago           |
| Detroit     | https://transparent.city/c/detroit           |
| Denver      | https://transparent.city/c/denver            |
| Cincinnati  | https://transparent.city/c/cincinnati        |
| NYC         | https://transparent.city/c/new-york-city     |
| Austin      | https://transparent.city/c/austin            |
| Seattle     | https://transparent.city/c/seattle           |

Confirm the live list before each run:
`curl -s https://api.transparent.city/api/public/cities/sitemap | jq '[.[] | select(.is_launched) | .slug]'`

### QA appendix state

Known outages and known lags are persisted in `scripts/weekly-qa/state.json` and committed
back to the repo by the GitHub Actions workflow after each run. Do not edit this file manually.
